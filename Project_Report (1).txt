## 3. 📌 Abstract

This project extends a basic Prolog family-relationship program into a complete **kinship reasoning engine**. The basic version could answer simple queries such as parent, sibling, grandparent and ancestor. The advanced version can additionally **identify the exact relationship between any two people** (for example "second cousin", "first cousin once removed", "half-brother" or "great-grandfather"), **explain its answer** by showing the common ancestor and both family paths, **validate its own knowledge base** for logical inconsistencies, and **answer questions typed in English** using a Definite Clause Grammar (DCG).

The knowledge base contains 19 people across four generations, with gender, birth and death years, parents, marriages and a previous marriage. All relationships beyond these base facts are derived through logical rules. The project demonstrates knowledge representation, recursion, search, constraint checking and natural-language parsing, which are core ideas of symbolic Artificial Intelligence.

The system has seven modules:

2. **Basic relations:** father, mother, sibling, grandparent, uncle, aunt, cousin, ancestor and others
3. **Relationship calculator:** names any relationship between two people

5. **Integrity validator:** checks data consistency
6. **Natural-language interface:** DCG grammar for English questions
7. **Utilities:** statistics, generations, Graphviz export and self-tests

## 7. 🧩 Implementation Details

### 7.1 Basic relations

```prolog
father(X, Y) :- parent(X, Y), male(X).
mother(X, Y) :- parent(X, Y), female(X).
grandparent(X, Y) :- parent(X, Z), parent(Z, Y).
uncle(X, Y) :- parent(Z, Y), sibling(X, Z), male(X).
aunt(X, Y)  :- parent(Z, Y), sibling(X, Z), female(X).
cousin(X, Y) :- parent(A, X), parent(B, Y), sibling(A, B), X \== Y.
```

**Sibling** requires a shared parent and a different person. A helper with a cut (`shares_parent/2`) prevents the same pair being reported once for each shared parent:

```prolog
sibling(X, Y) :- person(X,_,_,_), person(Y,_,_,_), X \== Y, shares_parent(X, Y).
shares_parent(X, Y) :- parent(Z, X), parent(Z, Y), !.
```

**Full and half siblings** are separated by comparing the complete set of parents:

```prolog
full_sibling(X, Y) :- sibling(X, Y), setof(P, parent(P, X), Ps), setof(P, parent(P, Y), Ps).
half_sibling(X, Y) :- sibling(X, Y), \+ full_sibling(X, Y).
```

### 7.2 Recursive relations

```prolog
ancestor(X, Y) :- parent(X, Y).                 % base case
ancestor(X, Y) :- parent(X, Z), ancestor(Z, Y). % recursive case
descendant(X, Y) :- ancestor(Y, X).
```

### 7.3 Relationship calculator (main novelty)

Every blood relationship is determined by two numbers: how many generations each person is below their **nearest common ancestor**.

**Step 1: find ancestors with distances**

```prolog
up(X, X, 0).
up(X, A, N) :- parent(P, X), up(P, A, N0), N is N0 + 1.
```

**Step 2: find the nearest common ancestor.** `closest_common/5` collects every common ancestor, keeps the pair of distances (Da, Db) with the smallest total, and counts how many ancestors sit at that position. Two ancestors means the link runs through a couple (a **full** relation). One ancestor means a **half** relation.

**Step 3: convert (Da, Db) into a name**

| (Da, Db) | Relationship of X to Y |
| -------- | ---------------------- |
| (0, 1) | father / mother |
| (0, n ≥ 2) | grandparent, great-grandparent, ... |
| (1, 0) | son / daughter |
| (n ≥ 2, 0) | grandson, great-grandson, ... |
| (1, 1) | brother / sister (half- if only one parent shared) |
| (1, n ≥ 2) | uncle / aunt, great-uncle / aunt |
| (n ≥ 2, 1) | nephew / niece, great-nephew / niece |
| (a ≥ 2, b ≥ 2) | cousin: degree = min(a, b) − 1, times removed = \|a − b\| |

**Worked examples**

* aarav and myra are both 3 generations below harish, so (3, 3) gives degree 2 and removed 0: **second cousin**.
* arjun is 2 generations below harish and myra is 3, so (2, 3) gives degree 1 and removed 1: **first cousin once removed**.
* sameer and dev share only kiran, so (1, 1) with one common ancestor: **half-brother**.

**Marriage-based relations.** When no blood relation exists, the engine checks spouse, ex-spouse, parent-in-law, child-in-law and sibling-in-law (for example, meena is the **sister-in-law** of radha because meena's husband mohan is radha's brother).

### 7.4 Explanation facility

`explain(X, Y)` prints the relationship, the nearest common ancestor, and the path from that ancestor down to each person, so every answer can be justified.

### 7.5 Integrity validator

`validate/0` collects and reports the following problems:

* a person mentioned in a fact who has no `person/4` record
* a person with more than two recorded parents
* a person who died before being born
* a parent less than 15 years older than a child
* a parent who died more than a year before the child's birth
* a **cycle** (a person who is their own ancestor)
* a warning when married people are close blood relatives

Cycle detection uses a list of already-visited people so the check itself can never loop forever, even on faulty data:

```prolog
climbs(A, T, Seen) :-
    parent(P, A),
    (   P == T -> true
    ;   \+ memberchk(P, Seen), climbs(P, T, [P|Seen]) ).
has_cycle(X) :- climbs(X, X, [X]).
```

The kinship check is skipped when a cycle exists, because computing ancestry on cyclic data would not terminate.

### 7.6 Natural-language interface (DCG)

A Definite Clause Grammar converts English questions into Prolog goals:

```prolog
question(call(R,X,Y), X) --> [who], be, opt_the, relword(R), [of], person_name(Y).
question(relationship(A,B,N), N) --> [how, is], person_name(A), [related, to], person_name(B).
question(age_now(P,Age), Age) --> [how, old, is], person_name(P).
```

Supported question styles:

* `ask('Who is the aunt of aarav?')`
* `ask('Who are the children of harish?')`
* `ask('How is aarav related to myra?')`
* `ask('How old is mohan?')`

The input is lower-cased, punctuation is removed, the words are split into a list, and `phrase/2` matches the list against the grammar. Only people who exist in the knowledge base are accepted as names.

### 7.7 Generations, ages and statistics

* `generation/2` computes how far a person is from the oldest generation. People with no recorded parents (in-laws) take the generation of their partner, so the whole family lines up correctly.
* `age_now/2` and `alive_in/2` use birth and death years.
* `family_stats/0` reports total members, living members, number of generations, the oldest living person and the person with most children.
* `export_dot/1` writes a Graphviz file with blue/pink boxes for gender, solid arrows for parents and dashed red lines for marriages.

## 9. 🔍 Working Explanation

* The program loads the **knowledge base** from `family_data.pl`.
* **Rules** derive direct relations such as father, sibling and aunt from the base facts.
* **Recursion** in `ancestor/2` and `up/3` allows relationships of any depth to be traced.
* The **relationship calculator** finds the nearest common ancestor of two people, measures the generation distance on each side, and maps the pair of distances to a relationship name.
* The **explainer** replays the paths so the answer can be checked.
* The **validator** applies consistency rules to the data and reports violations.
* The **grammar** converts a typed English question into a Prolog goal, runs it, and prints the answers.
* Prolog's built-in **unification and backtracking** search through all possibilities, so one predicate can be queried in both directions (for example `parent(harish, X)` and `parent(X, mohan)`).

## 10. 🧪 Testing

The built-in `run_tests/0` predicate runs 38 automated checks and prints PASS or FAIL for each:

* 15 checks of basic relations (including empty results such as `uncle(X, aarav)`)
* 13 checks of the relationship calculator (blood, in-law, ex-spouse and unrelated people)
* 4 checks of generations and age
* 2 checks of the natural-language grammar
* 4 checks of the validator: the base data must be valid, and the validator must detect a deliberately inserted cycle, a missing person and an impossible age gap (the faulty facts are removed again after each check)

## 12. ⚠️ Limitations

* Only two parents per child are expected; adoption and step-parents are not modelled
* The grammar understands only three question patterns, so it is a demonstration rather than full natural-language processing
* `relationship/3` reports the closest relationship only, even if two people are related in more than one way
* Aunts and uncles by marriage (the spouse of a parent's sibling) are not named
* The dataset is small (19 people)
* No graphical user interface (only a Graphviz export)
